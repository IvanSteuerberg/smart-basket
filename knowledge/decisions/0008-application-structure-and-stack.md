# Context

The system runs with Docker Compose on the author's laptop ([NFR-10](/requirements/non-functional.md)), with one PostgreSQL ([0003](/decisions/0003-postgresql-single-database.md), [0007](/decisions/0007-data-model.md)), a local LLM through Ollama on the integrated Arc GPU ([0005](/decisions/0005-local-first-ai-models.md)), a routing engine ([0002](/decisions/0002-routing-in-three-layers.md)) and periodic collection with a real browser ([0006](/decisions/0006-data-collection-with-a-real-browser.md)). Neither the language nor the frameworks had been chosen. The author may later move the system to a VPS and build a native Android app, so the structure should not depend on the laptop or on a web-only client.

Docker on Windows cannot reach the Arc GPU, and the viability study reached every chain's catalog without a login (Alimerka as a guest).

# Decision

1. **One repository:** a Python backend package, a React web app and the Compose file. Benchmarks and one-off scripts stay in `experiments/`.
2. **Python for the whole backend** (FastAPI), one package with modules for ingestion (one adapter per chain, [NFR-12](/requirements/non-functional.md)), product matching, the recommender (rule-based preprocessor, agent, tools and optimizer), BI refresh jobs and the HTTP API. Playwright, the optimizer libraries, embeddings, the Ollama client and the benchmark code are all Python.
3. **Compose services:**

   | Service | Contents |
   | --- | --- |
   | `db` | PostgreSQL 18 with PostGIS and pgvector; transactional schema and `bi` schema |
   | `api` | Backend image serving the HTTP API |
   | `worker` | Same image with another command: a scheduler (APScheduler) runs ingestion per chain, matching and the BI refresh |
   | `routing` | Valhalla with the León OpenStreetMap extract ([0009](/decisions/0009-valhalla-routing-engine.md)) |
   | `web` | Caddy serving the built React app and proxying `/api` to `api` |
   | `metabase` | Metabase OSS, read-only on `bi` |

4. **Ollama runs natively on the host** to use the Arc GPU; the backend reaches it at a configurable URL (`host.docker.internal:11434` on the laptop).
5. **The HTTP API (JSON, OpenAPI generated by FastAPI) is the only contract.** Clients hold no business logic; they only keep the user's personal data on the device, with the shape described in the [data model](/architecture/data-model.md#browser-storage).
6. **Web client:** React with Vite and TypeScript, single-page, mobile-first and installable as a PWA, with personal data in browser storage.
7. **Scraping runs in the `worker` container** with Playwright's Chromium. If a site rejects a headless browser, the adapter runs it with a window under a virtual display (Xvfb); the same code can run on the host if a chain ever requires the author's browser session.
8. **Versions:** the latest stable release of each tool and library when the skeleton is created, pinned to exact versions (uv for Python and its dependencies, ruff for formatting and linting); if a library does not yet support the latest Python, the previous one is used and the reason recorded.
9. **Configuration through environment variables** (a `.env` file, not versioned): database URL, LLM provider and URL, optional Gemini key. The same images run on the laptop and on a server.

# Consequences

* `docker compose up` starts the whole system; the demo needs only Docker and Ollama.
* A move to a VPS keeps the same images and Compose file, with Caddy serving HTTPS for a domain. What changes: without the Arc GPU the LLM runs on CPU (Ollama in a container) or Gemini becomes primary ([0005](/decisions/0005-local-first-ai-models.md) lists this as a reason to revisit); the server needs memory for PostgreSQL, the routing engine and Chromium; backups become necessary; and scraping from a data-centre address may be blocked more often than from a home connection.
* A native Android app (Kotlin) would be one more client of the same API, keeping personal data on the phone with the same shape. Until then the PWA covers mobile.
* Two scheduled processes share one image, so ingestion, matching and the API never drift apart in their view of the schema.
* The first runs must confirm that Carrefour, Dia and Alimerka, which reject plain HTTP clients, accept Chromium in the container.

# Revisit when

* A chain rejects the containerized browser or requires a login for its catalog.
* The system moves to a VPS (also revisit [0005](/decisions/0005-local-first-ai-models.md)).
* Work starts on the Android app or on user accounts ([Path to user accounts](/requirements/scope.md#path-to-user-accounts)).
