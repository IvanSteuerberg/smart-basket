The course uses project-based learning, assessed from two sides: outward, the lessons learned; inward, the content, which lives in the GitHub repository and its README.

# Deliverables

| Deliverable | Notes |
| --- | --- |
| **Report** | PDF, written in LaTeX like the other academic documents in `docs/` |
| **Presentation** | 15-20 slides, based on the report |
| **Video** | Based on the presentation, with screen and camera; clear, confident and neutral, without unnecessary decoration on screen. Linked from the README |
| **README** | The project's content on GitHub, with the link to the video |

# Report structure

1. **Introduction.**
2. **Summary.**
3. **Tools used:** every tool and what it was used for, descriptively. One slide lists them all and names the most important.
4. **How it was done:** the problem solved. The project must answer an **opportunity**: a gap with respect to the status quo ([competitors](/product/competitors.md)).
5. **User guide:** access to the application and how to use it, also explained in the presentation. **At least two case studies**, defined as examples and deliberately extreme; no application is presented without them. Candidates: a student on foot with a short list in time mode against a family by car with a large weekly list in savings mode ([recommender evaluation](/evaluation/recommender-evaluation.md)).
6. **SWOT:** critical and honest analysis, with an adversarial audit. Limitations matter (months of work, the machine, resources); opportunities are future lines of work.
7. **Lessons learned:** simple, for the author and for anyone viewing the work. The prompt log and the activity log in `docs/` are the raw material.
